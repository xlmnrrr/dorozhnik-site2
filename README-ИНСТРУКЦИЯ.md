# ДОРОЖНИК — сайт и админка: пошаговая инструкция

## Что где лежит

| Файл | Назначение |
|---|---|
| `index.html` | Сайт. Тексты и фото берёт из `content.json` |
| `content.json` | Все тексты, пути к фото и подписи. Меняется из админки |
| `admin.html`, `admin.js`, `admin.css` | Админка |
| `privacy.html`, `consent.html`, `legal.css` | Политика обработки ПДн и Согласие (152-ФЗ). На сайте открываются в модальном окне |
| `assets/images/` | Фото в WebP |
| `assets/js/chat.js` | Чат-помощник «Задать вопрос» и калькулятор стоимости по площади (работает в браузере, без сервера) |
| `assets/js/fx.js` | Эффекты: прогресс прокрутки, параллакс, магнитные кнопки, подсветка и 3D-наклон карточек, курсор, запуск 3D и прелоадер |
| `assets/js/hero3d.js` | 3D-сцена главного экрана: ночная трасса, самосвал Volvo FMX с горячим асфальтом, фонарные столбы, фары, пар |
| `assets/vendor/three.custom.min.js` | Урезанная сборка Three.js r160 (MIT), ≈123 КБ в gzip — только нужные классы |
| `assets/images/cases/*.svg` | Иллюстрации «до / после» для блока «Наши объекты» — замените в админке на фото объектов |

> Сайт нельзя открывать двойным щелчком (адрес `file://`): браузер не даёт читать `content.json`, и вы увидите заглушку. Нужен сервер — GitHub Pages (ниже) или локально `python -m http.server 8000`, затем http://localhost:8000.

## 1. Однократная подготовка

### 1.1. Репозиторий и GitHub Pages
1. Создайте репозиторий на GitHub (например, `dorozhnik-site`) и загрузите в него все файлы **кроме** `.mcp.json` (он в `.gitignore`: там ключ Unsplash).
2. Репозиторий → **Settings → Pages → Build and deployment**: Source — *Deploy from a branch*, ветка `main`, папка `/ (root)` → **Save**.
3. Через 1–2 минуты сайт откроется по адресу `https://<ВАШ-ЛОГИН>.github.io/<РЕПОЗИТОРИЙ>/`.

### 1.2. Токен GitHub (fine-grained)
1. GitHub → аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. **Repository access** → *Only select repositories* → выберите репозиторий сайта.
3. **Permissions → Repository permissions → Contents: Read and write**. Больше ничего не нужно.
4. Срок действия — 90 дней или меньше. Нажмите **Generate token** и скопируйте значение (`github_pat_…`) — GitHub покажет его один раз.

## 2. Как войти в админку

1. Откройте `https://<ВАШ-ЛОГИН>.github.io/<РЕПОЗИТОРИЙ>/admin.html`.
2. Введите пароль **`admin123`** → **Войти** (пока вкладка открыта, повторно вводить не нужно: флаг хранится в `sessionStorage`).
3. В блоке «Подключение к GitHub» заполните:
   - `GITHUB_OWNER` — ваш логин (или организация);
   - `GITHUB_REPO` — имя репозитория;
   - Ветка — `main`;
   - `GITHUB_TOKEN` — токен из п. 1.2.
4. Нажмите **Проверить доступ** — должно появиться «Доступ есть… запись разрешена». Затем **Загрузить content.json**.
   Токен и остальные поля запоминаются в этом браузере (`localStorage`); кнопка **Забыть токен** удаляет токен.

## 3. Как изменить тексты

1. Откройте нужный раздел (Главный экран, Услуги, Наши объекты, Преимущества, Парк техники, Лицензии и СРО, Цифры, Вопросы и ответы, Контакты, Карта «Как нас найти», Чат-помощник, Подвал).
2. Правьте поля. У списков есть кнопки **+ Добавить**, **↑ ↓** (порядок) и **✕** (удалить).
3. Нажмите **Сохранить на GitHub** (кнопка внизу). Админка сама получает свежий `sha` файла и записывает `content.json` коммитом в репозиторий.
4. Через **1–2 минуты** (GitHub Pages пересобирает сайт) изменения увидят все посетители; если не видно — обновите страницу сочетанием Ctrl+F5.

### 3.1. Карта «Как нас найти» (вкладки «Офис» / «База»)
- **Локации** — вкладки карты. У каждой: подпись вкладки, заголовок, адрес, пояснение и **координаты**.
- Адрес базы сейчас временный — `г. Уфа, ул. Промышленная, 1`. Замените на настоящий.
- **Координаты** необязательны, но с ними метка встаёт точно и появляется кнопка «Построить маршрут». Как получить: Яндекс Карты → правый клик по точке → «Что здесь?» → скопируйте числа вида `54.735152, 55.958736` (сначала широта).
- Ключ API карт задаётся в коде (раздел 6.2). Без ключа вместо карты показывается аккуратная карточка с адресом и кнопкой «Открыть в Яндекс Картах».

### 3.2. Чат-помощник и калькулятор
- **Приветствие** — первое сообщение бота.
- **Базовые цены калькулятора, ₽ за единицу** — строительство, ремонт, благоустройство (за кв.м.), бетон (за куб.м.). Клиент выбирает услугу и вводит площадь, бот умножает: «Примерная стоимость для 500 кв.м.: от 500 000 ₽». Кнопка «Оставить заявку» подставляет в форму задачу и расчёт в поле «Комментарий». Сейчас стоят демонстрационные значения (1000 / 500 / 300 / 200) — замените на реальные.
- **Единицы измерения в калькуляторе** — как бот подписывает объём («кв.м.», «куб.м.»).
- **Пояснение под расчётом** — оговорка, что это не оферта.
- Ответы на вопросы бот берёт из раздела «Вопросы и ответы»: добавили вопрос в админке — бот начал на него отвечать.

### 3.3. Наши объекты, Парк техники, Лицензии и СРО
- **Наши объекты** — карточки со слайдером «до / после». Сейчас вместо фото стоят иллюстрации (`assets/images/cases/`) и типовые описания работ. Замените на реальные объекты: у каждой карточки два фото — «Фото „до“» и «Фото „после“». Снимайте с одной точки и в одном кадре — тогда слайдер показывает разницу наглядно. Если у карточки нет ни одного фото, она не показывается; если нет карточек — скрывается весь блок.
- **Парк техники** — карточки с силуэтом (поле «Силуэт техники»: самосвал / каток / асфальтоукладчик) и характеристиками. Указаны типовые ТТХ классов техники — поправьте под свои машины. Кнопка «+ Добавить фото» ставит фото вместо силуэта.
- **Лицензии и СРО** — бейджи для закупочной аудитории. Поле «Ссылка» необязательно (только `https://`), например на поиск контрактов в ЕИС по ИНН.

## 4. Как заменить фото на свои

1. В разделе с фото (Главный экран → Фото; Услуги → карточка → Фото; Преимущества → «Свой бетонный завод» → Фото) нажмите **«Заменить фото»** и выберите файл (JPG, PNG или WebP).
2. Браузер сам уменьшит снимок до 1600 px по ширине и сожмёт в WebP — в предпросмотре появится новое фото.
3. Заполните **«Описание фото (alt)»** — коротко, что на снимке (это важно для доступности и поиска) и **«Автор / источник фото»**.
4. Нажмите **Сохранить на GitHub**: админка сначала загрузит файл в `assets/images/`, затем обновит `content.json`.
5. **+ Добавить фото** в карточке, где его нет, и **Убрать фото из карточки** — работают для Услуг, Преимуществ и Парка техники. Фото «до / после» в «Наших объектах» меняются тем же способом.
6. Если вы заменили **все** фото Unsplash своими, строку «Фотографии: Unsplash» в разделе «Подвал сайта» можно убрать.

Советы по файлам: снимки хотя бы 1200 px по ширине, горизонтальные для карточек; вес итогового WebP обычно 100–300 КБ.

## 5. Безопасность — что важно знать

- Пароль `admin123` записан в `admin.js` и **виден любому, кто откроет исходный код**. Это лишь замок от случайного захода. Реальную защиту даёт токен: без него сохранить ничего нельзя.
- Токен лежит в `localStorage` этого браузера. Не вводите его на чужих компьютерах, а после работы нажимайте **Забыть токен**. Если токен мог попасть не туда — отзовите его в GitHub и создайте новый.
- Страница админки закрыта от индексации (`noindex`) и от внешних скриптов (CSP). Все значения выводятся через `textContent`, а не `innerHTML`.
- Сменить пароль: откройте `admin.js`, в начале найдите `ADMIN_PASSWORD` и замените значение.

## 6. Что ещё нужно сделать до запуска (юридически)

1. **Обработчик заявок.** В `index.html` в блоке `CONFIG` задан `FORM_ENDPOINT` — функция Yandex Cloud, которая пересылает заявку в сообщения ВКонтакте. **Прежде чем заявки начнут доходить, функцию нужно поправить — см. раздел 7.** Обработчик должен хранить данные на серверах в РФ (ст. 18 ч. 5 152-ФЗ; в Политике это заявлено).
2. **Уведомление Роскомнадзора** об обработке персональных данных и приказ о назначении ответственного за обработку — организационные требования 152-ФЗ, вне кода.
3. **Проверка юристом.** Тексты `privacy.html` и `consent.html` — рабочая основа по ст. 9 и 18.1 152-ФЗ. Сроки хранения (12 месяцев для заявок без договора) и состав мер защиты подставлены типовые; приведите их в соответствие с реальной практикой компании.
4. **Метрика.** Если подключите Яндекс.Метрику, впишите её номер в `ANALYTICS_COUNTER_ID` — счётчик загрузится только после «Принять все» в cookie-баннере.
5. **Домен.** После публикации раскомментируйте/добавьте в `<head>` `canonical`, `og:url`, `og:image` (см. TODO в `index.html`).
6. **Unsplash.** Фото взяты с Unsplash; в подвале указано «Фотографии: Unsplash». Авторы перечислены в поле `credit` каждого фото в `content.json`.

## 6.2. Ключ Яндекс Карт
1. Откройте https://developer.tech.yandex.ru → «Подключить API» → **JavaScript API и HTTP Геокодер**.
2. В настройках ключа ограничьте его вашим доменом (HTTP Referer) — иначе ключ смогут использовать чужие сайты.
3. Вставьте ключ в `YANDEX_MAPS_API_KEY` в `index.html` (ключ уже вписан). Скрипт карт загрузится только когда посетитель долистает до раздела «Как нас найти» — на скорость первого экрана это не влияет.

## 6.3. 3D и производительность
- 3D-сцена включается только на мощных устройствах: компьютер с мышью и экраном от 1024 px, 4+ ядер, 4+ ГБ памяти — самосвал с PBR-материалами, фары, маячки, пар, фонарные столбы (`InstancedMesh`), прелоадер в области сцены.
- На телефонах и планшетах (6+ ядер) — облегчённая версия «от первого лица»: только разметка и огни, 30 кадров/с, без самосвала и столбов. Она стартует с первым касанием или прокруткой — до этого виден статичный постер, и загрузка страницы не тормозит.
- Тяжёлые декоративные эффекты (кастомный курсор, шум поверх страницы, побуквенное появление заголовков, перелив градиента, 3D-наклон карточек) работают только на компьютере с мышью и выключаются при «Уменьшении движения».
- Не включается при «Уменьшении движения» в системе, в режиме экономии трафика, на медленной сети, без аппаратного WebGL. Тогда показывается статичная картинка той же сцены (SVG внутри страницы, без загрузки файлов).
- Библиотека грузится **после** полной загрузки страницы, когда браузер свободен, поэтому LCP/CLS не страдают.
- Сторож FPS: если сцена тормозит — снижает разрешение; если всё равно тормозит — последний кадр остаётся картинкой, ресурсы видеокарты освобождаются (`dispose`), а в этой вкладке 3D больше не загружается.
- Пересобрать `three.custom.min.js` (нужен Node.js): во временной папке `npm i three@0.160.0 esbuild@0.20.2`, файл `entry.js` с `export { ...нужные классы } from 'three'` (список — в начале `assets/js/hero3d.js`), затем `npx esbuild entry.js --bundle --format=esm --minify --legal-comments=inline --outfile=three.custom.min.js`.

## 7. Функция Yandex Cloud для заявок: что нужно исправить

Проверка 27.10.2026 показала две проблемы на стороне функции `d4ek5vqamvqv0a6j3k7s` (сайт к ним уже готов):

1. **CORS.** На предварительный запрос браузера (`OPTIONS`) функция отвечает без заголовка `Access-Control-Allow-Headers`, поэтому браузер блокирует отправку JSON. Запрос с `Content-Type: text/plain` функция отклоняет с кодом 400 (скорее всего, Yandex Cloud передаёт такое тело в base64, а функция его не декодирует).
2. **«VK error» (код 500).** Корректную заявку функция принимает, но запрос к API ВКонтакте завершается ошибкой — сообщение не доставляется. Проверьте токен (права на сообщения), `peer_id`/ID получателя, включены ли сообщения сообщества, передаётся ли `random_id` и версия API `v`. Текст ошибки ВК смотрите в журнале функции: консоль Yandex Cloud → Cloud Functions → функция → «Логи».

Минимальная правка обработчика (Node.js):

```js
const CORS = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Methods': 'POST, OPTIONS',
  'Access-Control-Allow-Headers': 'Content-Type',
  'Access-Control-Max-Age': '86400'
};

module.exports.handler = async (event) => {
  if (event.httpMethod === 'OPTIONS') return { statusCode: 204, headers: CORS, body: '' };

  // тело может прийти в base64 (например, при Content-Type: text/plain)
  const raw = event.isBase64Encoded ? Buffer.from(event.body || '', 'base64').toString('utf8') : (event.body || '');
  let lead;
  try { lead = JSON.parse(raw); } catch (e) { return { statusCode: 400, headers: CORS, body: 'Bad Request' }; }

  // ... ваша отправка в ВКонтакте (lead.name, lead.phone, lead.email, lead.taskLabel, lead.comment, lead.page) ...

  return { statusCode: 200, headers: { ...CORS, 'Content-Type': 'application/json' }, body: JSON.stringify({ ok: true }) };
};
```

Сайт сначала отправляет заявку как `text/plain` (без предварительного запроса), а если функция ответит 400/415 — повторяет с `application/json`. Поэтому заработает любой из двух вариантов правки: декодирование base64 или заголовки CORS. Лучше сделать оба.

Что видит посетитель при сбое: понятное сообщение (нет интернета / сервер не ответил / сервер не принимает заявки), введённые данные остаются в форме, кнопка меняется на «Отправить ещё раз», рядом — телефон.
